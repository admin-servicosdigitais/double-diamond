# Specs Técnicas — Antecipação de Recebíveis

## US-01: Widget de valor disponível

**API Contract**:
- `GET /api/v1/anticipation/availability?tenant_id={tid}`
- Response: `{ available_amount: number, min_amount: number, max_amount: number, base_rate: number, eligible: boolean, reason?: string }`
- Headers: `Authorization: Bearer {token}`, `X-Tenant-ID: {tid}`
- Erros: `401 (token inválido)`, `403 (tenant sem permissão)`, `404 (tenant não encontrado)`

**Regras de negócio**:
1. Elegibilidade: tenant ativo há > 6 meses, volume transacional > R$ 10k/mês, sem inadimplência > 30 dias
2. Valor disponível = 80% do volume de recebíveis dos próximos 30 dias
3. Cache de 15min para disponibilidade (invalidar em nova transação)

**Observabilidade**:
- Log: `anticipation.availability.checked` com tenant_id, eligible, amount
- Métrica: `anticipation_availability_requests_total`, `anticipation_eligible_ratio`
- Alerta: eligible_ratio < 50% (pode indicar bug no scoring)

## US-03: Confirmação e execução

**API Contract**:
- `POST /api/v1/anticipation/execute`
- Request: `{ tenant_id: string, amount: number, idempotency_key: string }`
- Response: `{ anticipation_id: string, net_amount: number, rate: number, iof: number, estimated_deposit: datetime, status: "approved"|"rejected" }`
- Erros: `400 (valor fora do range)`, `409 (idempotency conflict)`, `422 (elegibilidade mudou)`, `502 (parceiro indisponível)`

**Fluxo técnico**:
1. Validar elegibilidade (cache-first, fallback para cálculo)
2. Chamar API do parceiro financeiro com dados da operação
3. Registrar operação no banco (status: pending)
4. Receber callback do parceiro → atualizar status
5. Notificar PME via webhook + in-app
