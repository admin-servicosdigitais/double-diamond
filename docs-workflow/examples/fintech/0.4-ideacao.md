# Alternativas de Solução — Antecipação de Recebíveis

**Referência**: OPP-20260409-001

## Alternativa A: Marketplace de antecipação
- **Abordagem**: conectar PMEs a múltiplas antecipadores via API, exibindo ofertas competitivas
- **Esforço**: G (4-5 meses) — múltiplas integrações
- **Risco principal**: dependência de terceiros para SLA e UX
- **Impacto esperado**: taxa mais competitiva para o cliente, mas experiência fragmentada

## Alternativa B: Antecipação integrada com parceiro único (white-label)
- **Abordagem**: parceria com uma fintech de crédito, integração profunda, experiência 100% dentro da plataforma
- **Esforço**: M (2-3 meses) — uma integração, UX própria
- **Risco principal**: concentração em um parceiro
- **Impacto esperado**: experiência fluida, time-to-market rápido

## Alternativa C: FIDC próprio
- **Abordagem**: operar fundo próprio com capital da empresa, controle total de taxa e aprovação
- **Esforço**: GG (6-12 meses) — regulação, capital, operação
- **Risco principal**: capital intensivo, risco de crédito no balanço
- **Impacto esperado**: margem máxima, mas complexidade operacional e regulatória

# Conceito Escolhido — Antecipação White-label

**Alternativa selecionada**: B — Antecipação integrada com parceiro único

## Descrição do conceito
PME acessa a tela de antecipação dentro da plataforma, vê quanto tem disponível para antecipar, simula valores e taxas, e confirma com um clique. O dinheiro cai na conta em até 1h. Toda a experiência é seamless, sem redirecionamento.

## Jornada proposta
1. PME acessa dashboard → vê widget "R$ X disponível para antecipação"
2. Clica → tela de simulação com valor, taxa e prazo
3. Ajusta valor → confirma antecipação
4. Aprovação instantânea (scoring por dados transacionais)
5. Dinheiro na conta em até 1h
6. Acompanha no extrato da plataforma

## Arquitetura em alto nível
- **Frontend**: componente React no dashboard existente
- **Backend**: API Gateway → serviço de antecipação → API do parceiro financeiro
- **Dados**: scoring engine usando dados transacionais (volume, frequência, inadimplência histórica)
- **Multi-tenancy**: tenant_id em todas as operações, isolamento de dados financeiros

## Trade-offs aceitos
| Ganhamos | Abrimos mão | Por que é aceitável |
|----------|-------------|-------------------|
| Time-to-market de 2-3 meses | Margem menor (parceiro fica com parte) | Validamos rápido; FIDC pode vir na fase 2 |
| UX integrada | Flexibilidade de taxa (depende do parceiro) | Parceiro aceita taxa mínima de 1.8% |
| Baixo risco regulatório | Dependência de um parceiro | Contrato com SLA e cláusula de saída |

## Riscos do conceito escolhido
| Risco | Prob | Impacto | Mitigação |
|-------|------|---------|-----------|
| Parceiro fora do ar | Baixa | Alto | Circuit breaker + fallback para solicitação manual |
| Inadimplência acima do esperado | Média | Alto | Limites conservadores no MVP + revisão mensal |
| UX percebida como "não é do banco" | Baixa | Médio | Branding 100% white-label |
