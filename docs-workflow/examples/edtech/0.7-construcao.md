# Specs Técnicas — Trilhas Adaptativas

## US-01: Assessment inicial

**API Contract**:
- `GET /api/v1/trails/{trail_id}/assessment?tenant_id={tid}&learner_id={lid}`
- Response: `{ assessment_id: string, questions: [{ id, text, options: [{ id, text }], difficulty: 1-3 }], time_limit_seconds: 300 }`
- `POST /api/v1/assessments/{id}/submit`
- Request: `{ answers: [{ question_id, option_id }] }`
- Response: `{ level: "beginner"|"intermediate"|"advanced", score: number, confidence: number, trail_config: { modules: [{ id, title, skipped: boolean }] } }`

**Regras de negócio**:
1. 10-15 questões com dificuldade progressiva (adaptive testing simplificado)
2. Score 0-40 = Iniciante, 41-70 = Intermediário, 71-100 = Avançado
3. Se confidence < 60%, sugerir que learner revise classificação
4. Assessment pode ser refeito 1x por trilha

**Observabilidade**:
- Log: `assessment.completed` com learner_id, tenant_id, level, score, time_taken
- Métrica: `assessment_completion_rate`, `level_distribution` (por tenant)
- Alerta: se > 80% classificados como mesmo nível (assessment pode estar enviesado)

## US-03: Trilha reorganizada

**Fluxo técnico**:
1. Buscar configuração da trilha (content_map por nível)
2. Filtrar módulos baseado no nível do learner
3. Montar response com módulos ativos + módulos pulados (acessíveis)
4. Registrar progresso isolado por tenant_id + learner_id

# Plano de Testes — Trilhas Adaptativas

## Casos de teste prioritários
| ID | Tipo | Cenário | Input | Expected |
|----|------|---------|-------|----------|
| TC-01 | Unit | Classificação por score | Score 35 | Level: beginner |
| TC-02 | Unit | Classificação limítrofe | Score 41 | Level: intermediate |
| TC-03 | Integ | Assessment completo | 10 respostas | Classificação + trilha configurada |
| TC-04 | E2E | Happy path: assessment → trilha → módulo | Learner novo | Trilha adaptada carrega corretamente |
| TC-05 | E2E | Pular assessment | Clica "pular" | Trilha inicia como beginner |
| TC-06 | Perf | 500 assessments simultâneos | 500 concurrent | p95 < 2s |

## Testes de multi-tenancy
| Cenário | O que valida |
|---------|-------------|
| Learner de tenant A | Não vê conteúdo customizado de B |
| Assessment de tenant A | Dados não aparecem no report de B |
| Content map por tenant | Tenant pode ter módulos extras por nível |
